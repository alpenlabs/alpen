# Checkpoint performance reports

This binary measures the SP1 execution cycles and gas needed to verify a
checkpoint, including its block transitions and DA reconstruction. These are
the primary metrics for comparing checkpoint guest performance. It executes the
guest without generating a proof, so full proof-generation latency is outside
this report.

## Run the checkpoint benchmark

From the repository root, use the toolchain from
`.github/workflows/prover.yml` and build the real checkpoint ELF with matching
runtime parameters:

```sh
CHECKPOINT_RUNTIME_PARAMS_PATH="$PWD/.github/fixtures/checkpoint-runtime-params.json" \
BUILD_ELF=1 SP1_PROVER=light \
cargo run --locked --profile prover-ci -p strata-provers-perf -- --programs checkpoint
```

Checkpoint is the only guest and runs by default. `--programs checkpoint` remains
accepted for existing CI and `just` commands; other program names are rejected.

The fixture uses test runtime parameters; its regression test checks that these
match the CI fixture. Debug/mock guest artifacts are not valid cycle benchmarks.

## Workload

`mixed-epoch-v1` is deterministic: 64 ledger accounts, five blocks after terminal
genesis, and three transactions. It exercises inbox delivery and consumption,
transfers, a bridge withdrawal, predicate rotation, a deposit, a malformed
deposit routed to limbo, and an epoch-terminal drain. Manifests arrive in several
blocks. The DA witness comes from the production accumulating-state replay path.

The active account starts with `AlwaysAccept`, then rotates to an SP1 Groth16
predicate. The other 62 snark accounts store SP1 Groth16 predicates generated by
the production key provider with a fixed synthetic program ID. This measures
the storage/hashing cost of actual verifier encodings, but does **not** execute
real EE proof verification.

## Compare in CI

Open baseline and candidate PRs using the same benchmark code, common base,
dependency lockfile, and runtime parameters. The existing prover workflow runs
both without workflow edits. Compare the checkpoint cycles/gas in the SP1
execution-results table, and link the two job logs with their measured percentage
differences in the final PR description. The logs also identify the guest
artifact (SP1's zero-padded verifying-key hash) and workload.

The report prints the PR head SHA and GitHub's tested merge SHA separately. Keep
the workload, toolchain, Cargo profile, and executor configuration equal.
Guest cycles/gas provide the comparison metrics; elapsed times from different
hosted runners are not a regression criterion.
